Qualité, fiabilité et préparation au déploiement

17 octobre 2026 · main @ 68dd869 (tag 0.1.0) · code, tests, CI, sécurité, exploitation, UX

La conception est d'un niveau rare pour un projet de cet âge ; ce qui manque, c'est la preuve qu'elle tient en dehors du poste de développement.

La stratégie de test est exemplaire et, en local, tout est vert : 747 tests Core, 259 Storage, 363 Server, 757 Vitest, couverture de Core à 93,6 %. Mais aucune exécution de la CI GitHub n'a encore été verte : 7 e2e échouent de façon reproductible, la fumée desktop échoue sous Linux et Windows, le workflow nightly est un YAML invalide. Mutation testing, restauration de sauvegarde, release et signature n'ont jamais été exécutés.

Verdict par usage

Démo, usage personnel local

Prêt.

Serveur interne, équipe de confiance

Presque : corriger B1 à B4, puis une semaine de CI verte, nightly compris.

Desktop pour utilisateurs externes

Pas encore : release exécutée de bout en bout, signature, fumée verte sur les 3 OS.

Serveur exposé sur Internet

Pas encore : en plus, en-têtes de sécurité, anti-verrouillage, restauration testée.

Le dépôt est sur GitHub depuis le 17/10 : ces échecs sont ceux des toutes premières exécutions. Ils montrent que les tests attrapent de vraies régressions, mais aussi qu'ils n'étaient pas relancés avant chaque commit.

Points forts

Des documents qui servent

Règles Fnn.Rn, scénarios E2E-nn-nn, risques classés par gravité, décisions Q/P tranchées explicitement, traçabilité vérifiée automatiquement.

Domaine isolé et prouvé

Core sans IO, TimeProvider, propriétés CsCheck / fast-check sur l'ID, le parseur, l'héritage, l'arbre et la fusion (« aucun caractère perdu sans conflit »).

Une spec, deux implémentations

Les fixtures JSON pilotent xUnit et Vitest : une divergence de parseur devient visible au lieu de casser des liens.

Pas de mock de ce qu'on possède

Vrai SQLite, vrai serveur, vrai navigateur ; erable doctor vérifie la base laissée par les tests.

Le fuzzing a déjà payé

Dépassement de pile capable d'arrêter le serveur et temps quadratiques trouvés, corrigés par des limites partagées C#/TS.

Données protégées

WAL + synchronous = FULL, blobs écrits par rename atomique, crash tests sur le vrai processus, migrations testées v1→v4.

Sécurité traitée comme une fonctionnalité

Matrice d'autorisation sur tous les endpoints, jetons hachés, pièces jointes en sandbox, Markdown sans innerHTML.

Chaîne d'approvisionnement

Actions épinglées par SHA, Renovate, versions centralisées, Trivy, pnpm épinglé.

Notes de tâches honnêtes

Chaque tâche dit ce qui n'a pas été vérifié : c'est ce qui rend cet audit précis.
