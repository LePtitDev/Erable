# M0-06 — Internationalisation

- **Statut** : review
- **Jalon** : M0
- **Dépend de** : M0-02
- **Références** : §A-3.1, §A-11.1 (point 3), §T-8.2, F15.R1, décision Q1

## Objectif

Mettre en place i18next pour que chaque texte d'interface soit traduit dès le premier écran.

## Périmètre

- i18next + react-i18next ; ressources JSON par langue (`fr`, `en`, `de`, `es`) chargées paresseusement ; `fr` = référence.
- Clés anglaises hiérarchiques ; pluriels et interpolation.
- Dates et nombres via `Intl` selon la langue d'interface (« il y a 2 h », « 12 mars 2026 »), horloge injectable pour les tests.
- Test de parité : chaque clé de `fr` existe dans les trois autres langues avec les mêmes paramètres, et inversement.
- Règle ESLint interdisant les chaînes en dur dans le JSX (exceptions explicites).
- Pseudo-locale `xx` (textes allongés de 40 %, accentués) générée automatiquement, activable en dev.
- Séparer clairement **langue d'interface** (préférence utilisateur) et **langue du contenu** (projet).

## Critères d'acceptation

- [x] Test de parité vert ; une clé manquante en `de` le fait échouer.
- [x] Un texte en dur dans un composant fait échouer le lint.
- [x] Changement de langue sans rechargement sur la page « hello ».

## Points d'attention

- Les traductions `de` et `es` produites par l'agent sont à signaler comme « à relire par un locuteur natif ».

## Notes d'implémentation

- **i18next 26.4 + react-i18next 17.0** (`src/shared/i18n/`). Ressources `locales/{fr,en,de,es}.json`, clés anglaises hiérarchiques. `fr` (référence et repli) est embarqué ; `en`, `de`, `es` sont chargés à la demande (un chunk par langue, vérifié dans `dist/`).
- **Clés typées** : `CustomTypeOptions` déclare `fr.json` comme ressource ; une clé inexistante ou un paramètre oublié est une erreur de compilation.
- **Pluriels** : suffixes i18next (`_one`, `_many`, `_other`). Attention : `Intl.PluralRules` donne `one / many / other` pour **fr et es** (le `many` sert aux grands nombres ronds, « 1 million de pages ») ; le test exige donc toutes les catégories de chaque langue.
- **Dates et nombres** : `createFormatters(langue, horloge)` (`Intl.DateTimeFormat`, `RelativeTimeFormat`, `NumberFormat`) et hook `useFormatters()` ; horloge injectable via `ClockContext` (les tests utilisent le 13/10/2026 10:00 de features §1.4). Nombres dans les messages : `{{count, number}}`. La pseudo-locale formate comme le français.
- **Test de parité** (`parity.test.ts`) : mêmes clés de base dans les 4 langues dans les deux sens, mêmes paramètres d'interpolation, catégories de pluriel complètes. Vérifié : supprimer une clé de `de` le fait échouer.
- **Lint** : `eslint-plugin-i18next` (`no-literal-string`, mode `jsx-only` : texte **et** attributs JSX, hors attributs techniques). Exceptions explicites : tests, `src/test/`, `src/dev/`. Vérifié : `<p title="Bonjour">Texte en dur</p>` → 2 erreurs.
- **Pseudo-locale `xx`** générée à l'exécution depuis `fr` (accents, +40 %, crochets ; `{{…}}`, `$t(…)` et balises préservés), proposée dans le sélecteur **en dev seulement**. Pour les captures de M5-02, il faudra l'activer aussi dans le build e2e.
- **Langue d'interface ≠ langue du contenu** : i18next ne gère que l'interface et met à jour `<html lang>` ; le contenu portera `lang={langue du projet}` sur son conteneur (M1-11). Documenté dans `languages.ts`.
- Langue initiale : `<html lang>` (qu'injectera le backend avec la préférence, P-03 / M1-15), sinon langues du navigateur, sinon `fr`. `lang="fr"` retiré de `index.html` pour ne pas masquer cette détection.
- Page « hello » : sélecteur de langue et de thème, pluriel, date et version de l'API traduits. Vérifié dans le navigateur avec le vrai backend : bascule fr → de → xx → fr sans rechargement.
- **Traductions `de` et `es` produites par l'agent : à relire par un locuteur natif.**
- Bundle initial : 120,7 Ko gzip (i18next inclus).

**Vérification** : `pnpm -C src/web test` (85), `lint`, `typecheck`, `format:check`, `build`.
